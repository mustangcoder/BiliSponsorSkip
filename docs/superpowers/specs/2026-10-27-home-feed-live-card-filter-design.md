# 首页推荐直播卡片过滤设计

## 意图

在哔哩哔哩首页“推荐”频道中隐藏直播卡片，减少推荐视频流里与普通视频混排的直播内容。该功能使用独立开关，不与首页广告过滤绑定。

## 目标

- 新增“隐藏首页推荐直播卡片”独立开关，默认开启。
- 只过滤首页推荐流中结构化标记为直播的卡片。
- 模块总开关关闭或独立开关关闭时，完整保留宿主直播卡片。
- 在旧版或未来版本缺少目标字段时失败开放，不影响首页加载。

## 非目标

- 不处理直播分区、关注页直播动态、搜索结果、个人空间或详情页推荐。
- 不根据标题、角标文案或主播名称中的“直播”文字判断。
- 不改变现有“隐藏首页信息流广告”开关的语义。

## 已选方案

采用独立开关，并复用现有 `HomeFeedAdHook` 已覆盖的解析器和适配器提交链路。在 `BasicIndexItem` 进入首页列表时读取结构化 `goTo`、`cardGoto` 和 `uri` 字段；以下任一条件成立时认定为直播卡片并移除：

- `goTo` 或 `cardGoto` 精确等于 `live`、`live_rcmd`；
- `uri` 以 `bilibili://live/` 或 `https://live.bilibili.com/` 开头。

9.15.0 APK 中，`com.bilibili.pegasus.api.model.BasicIndexItem` 明确定义 `goTo`、`cardGoto` 和 `uri`。手机截图确认存在 `small_cover_v2` 直播卡片，而仅匹配 `goTo == "live"` 未能过滤；客户端推荐结构记录还使用 `live_rcmd` 和明确直播 URI，因此需要组合这些结构化信号。标题和 UI 文案仍不参与判断。

## 备选方案

- 并入“隐藏首页信息流广告”：改动较少，但广告与直播无法独立控制，未采用。
- 只按卡片视图类型判断：`small_cover_v2` 同时承载普通视频和直播，无法安全区分，未采用。
- 只保留 `cardGoto == "av"`：会删除番剧、课程等正常卡片，范围过宽，未采用。

## 实现边界

- 在首页卡片信号模型中增加 `goTo`、`cardGoto` 和 `uri`，新增组合结构化判断函数。
- 首页过滤过程分别计算广告过滤和直播过滤是否启用；任一条件命中时移除卡片。
- 日志区分广告与直播的移除数量，便于升级后诊断。
- 设置字段接入独立设置页、B 站内嵌设置页、镜像存储及双向 Bundle 同步。
- README 和 CHANGELOG 补充功能说明。

## 验证

- 单元测试确认 `goTo/cardGoto` 的 `live`、`live_rcmd` 和明确直播 URI 会被识别；`vertical_live`、`live_event`、普通视频和仅含“直播”标题的卡片不会误判。
- 测试广告开关与直播开关四种组合，确保二者互相独立。
- 测试关闭模块总开关时不做任何过滤。
- 运行全量单元测试与 Debug 构建，并在 9.15.0 补丁包中验证首页推荐直播卡片消失、普通视频和广告开关行为不回归。
